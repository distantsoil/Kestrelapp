Design proposal · October 2026

Kestrel, made legible

Kestrel does a lot and shows it all at once. The proposal keeps the orange and white identity and every feature, and changes how the work is organized: a sidebar that groups pages by what you are doing, a home page that answers "what needs me today", status you can see without reading a log, and a first run that walks you to a working system instead of a terminal.

What is wrong today

  • Nine equal tabs. Pipeline, Pursuits, Documents, Stories, Offers, Analytics, Sources, Settings and Dashboard sit in one row with no grouping. Nothing says where to start or where setup lives (Calibrate, Runs, Bench and About are only reachable from the command palette).
  • State is invisible. Whether the worker is running, which model is loaded, when the last scan happened, and whether Ollama is even up are either a small mono string in the top bar or a visit to kestrel doctor.
  • Tables for everything. The pipeline is a dense grid where the three numbers that matter (verdict, score, what to do) compete with seven that rarely matter.
  • First run is a terminal. The README says there is no setup window on purpose. For one engineer that was fine. For "extremely easy to set up" it is the single biggest gap, and a machine with no GPU has no path at all today.
  • Plain by default. One typeface at one size, one border color, every box a card. The eye has nothing to grab.

What the proposal keeps

  • Orange #D4622A and white, with dark mode as the same palette. The accent is used for the one thing that matters on each screen, not for everything.
  • Every page and every feature. Nothing is removed; pages are grouped and some are nested under the page they belong to.
  • The stack: Jinja templates, HTMX, Alpine, a hand-written stylesheet served from disk. No build toolchain is introduced.
  • The hard rules in the UI: the Tier 3 send still shows exactly what leaves the machine, document bullets stay the operator's own text, sample sizes stay stated.
Scope of this document: mockups and the reasoning behind them, for your edits. Implementation follows once you have cut what you do not want.
Color

Five schemes, both modes

The brown-and-orange dark mode is retired. The two chosen schemes come first. Each scheme keeps the Kestrel identity in light mode and uses a true neutral ground in dark mode, never a tinted brown. Pick one and every screen on this page re-skins. The verdict colors never change with the scheme: green apply, orange keep, amber review, red kill, in every scheme and both modes, so a state always reads the same. Only the ground, the action color and the links move.

Preview mode:
Decided: Paper and Indigo ships as the default; Graphite and Teal is the one alternate, selectable under Settings with light, dark or follow-system for each. The other three stay here for the record and are not built.
Screen 1

The shell and the home page

A left sidebar replaces the tab row. Pages are grouped into Work (what you do daily), Learn (what the system learns from you) and Setup (sources, models, settings). The bottom of the sidebar is a status rail that is always visible: worker state, model loaded, last scan, Ollama health. The home page answers one question, "what needs me today", in three columns: review, act, and what the system did overnight.

Screen 5

First run: a setup page instead of a terminal

The first time Kestrel opens, and any time preflight fails, it lands here. The first choice is how Kestrel will run: Local, Hosted, or Both; the remaining steps show as required or skipped accordingly. Each step is one line with a state, a plain explanation, and the exact command when the fix is yours to run. Steps that Kestrel can do itself (pull models, build the derived models, seed the config) have a button. The hardware profile is detected and named, with the models it implies, and a machine with no GPU is steered to Hosted. The same page is Setup › Models afterward, where the Local/Hosted switch also lives.

The visual system behind the screens

Color

Orange stays the accent and is spent on one thing per screen: the active nav item, the primary button, the selected row. Verdicts use a separate semantic set (green apply, orange keep, amber review, red kill) so the accent never competes with a state. Neutrals are warm, not grey, so the page reads as paper rather than a spreadsheet. Dark mode is the same palette on a warm dark ground.

Type

One sans for the interface, a mono for numbers and identifiers, and tabular figures everywhere a column of scores lines up. Sizes come from a five-step scale instead of per-element pixels. Labels in small caps with letter-spacing mark structure; headings are sentence case.

Components

Four building blocks cover every page: the row with a stripe (pipeline, pursuits, calibrate, quarantine), the card with a label (home, settings, org), the step (setup, doctor, bench) and the meter (dimension scores, progress, calibration). Fewer components means fewer decisions per page and a UI that reads the same everywhere.

Implementation cost

One stylesheet rewrite, a new base template with the sidebar and status rail, and the home, pipeline and setup pages reworked. Detail, documents and settings reuse their existing partials inside the new frame. No JavaScript framework; HTMX and Alpine stay. Estimated at three focused sessions, with the setup page first because it unblocks the cross-platform install story.
